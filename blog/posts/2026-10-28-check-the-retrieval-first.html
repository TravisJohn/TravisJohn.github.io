Check the Retrieval First

When an AI assistant gives a wrong answer, my first instinct used to be changing the prompt. Add a stricter instruction. Tell it to use only the provided context. Run it again.

Sometimes that helps. But with retrieval-augmented generation (RAG), the problem may have happened before the model received the question. If the right passage never reached it, prompt wording cannot bring that passage back.

That’s the principle guiding my next experiment with WhitePaper, a collection of sourced, interactive learning papers I’m building across AI, cloud and data engineering.

Look at what was retrieved

When a RAG answer goes wrong, I want to see the full trail: the question, the passages retrieved, the context sent to the model and the answer it produced.

The first check is simple: was the evidence needed to answer the question actually there?

If it was missing from the search results, I would investigate the content and retrieval process. If it appeared in the results but was dropped before the model saw it, I would investigate how the context was assembled. If the model received it and still answered incorrectly, then I would look at the generation step.

Those are different failures, and each needs a different fix.

Test retrieval before connecting a model

WhitePaper already organises its papers into topics, pages and passages. It does not have live RAG today. My plan is to start with one subject collection, turn its papers into searchable sections, and keep every section linked to its heading, sources and place in the reader.

Then I’ll write a small set of questions paired with the passages that should answer them. For each question, I’ll inspect the top search results. Did the supporting passage appear? Was it the right version? If the answer needs two passages, did retrieval find both?

This lets me improve the search before asking a model to write anything.

Let the answer acknowledge a gap

Once retrieval is working, I want readers to be able to ask questions across the papers and follow an answer back to its supporting passages.

I also want an honest response when the collection cannot support an answer: “I couldn’t find that in these papers.” That is more useful than a confident guess. It tells the reader where the limit is, and it tells me where the collection may need work.

The habit underneath it

Back when I was a finance analyst reconciling eggs against planning reports at San Miguel Purefoods, I learned to check the source before rewriting the report. A missing or mistimed input could make the final number look wrong.

I’m bringing that habit to WhitePaper: check the evidence first, then examine what the model did with it.

I’m looking for a few early testers who are learning AI, cloud or data engineering. You can explore WhitePaper now. If you’d like to help shape the upcoming RAG pilot, send me a message and tell me what question you’d want it to answer.
